# 个人本地发票工作台产品设计

- 日期：2026-08-31
- 状态：书面设计已确认，待按本地版实施计划开发
- 产品形态：双击启动、浏览器访问的本地网页工作台
- 目标用户：单个个人用户

## 1. 产品目标

建设一个只在个人 Mac 上运行的发票整理工作台。用户双击启动脚本后，系统在本机启动服务并自动打开浏览器；发票原件、SQLite 数据库、识别结果和导出文件均保存在用户选择的本地工作目录。

系统默认使用 Mac 自带的 Apple Vision OCR 和本地解析规则，不自动上传任何发票。只有用户明确点击“使用云端重新识别”时，当前发票才会发送到配置的云端 OCR 服务。

核心闭环保持不变：

```text
启动 → 上传 → 本地识别 → 查重 → 校对 → 管理状态 → 查看统计 → 导出 Excel/ZIP
```

## 2. 简化原则

### 2.1 保留

- PDF、OFD、JPG、JPEG、PNG 上传。
- 常见发票类型、日期、号码、开票方、购买方和金额字段识别。
- 文件级和业务级重复检测。
- 低置信度字段校对。
- 待报销、报销中、已报销三种状态。
- 月份、类型、金额和报销状态统计。
- 按月份和类型整理、规范重命名、Excel 与 ZIP 导出。
- 电脑与手机宽度下可用的响应式页面。
- 本地备份、恢复和可恢复删除。

### 2.2 删除

- 登录、注册、会话和多用户权限。
- PostgreSQL、远程数据库和数据库服务运维。
- S3、COS 等对象存储。
- Redis、pg-boss 等独立任务队列。
- 云端部署、域名、HTTPS 证书和服务器监控。
- 公司组织架构、部门、报销人、审批流和财务系统对接。
- 自动验真、自动报税和自动提交报销。
- 小程序、原生 App 和安装包。

## 3. 本地架构

```text
首次安装.command
    └── 检查 Node/pnpm、安装依赖、构建应用、创建工作目录

启动发票工作台.command
    ├── 检查现有进程
    ├── 启动本地 Node 服务
    ├── 绑定 127.0.0.1
    └── 打开浏览器
            ↓
      本地响应式网页
            ↓
  ┌─────────┼──────────┐
SQLite   本地文件系统   本地 OCR
                         ├── PDF 文字层
                         ├── Apple Vision
                         └── OFD 解析器
            ↓ 用户明确选择时
      云端 OCR 适配器
```

本地服务默认监听 `127.0.0.1:4876`，不监听 `0.0.0.0`，局域网设备不能直接访问。若端口被其他程序占用，启动器在 `4877—4885` 中选择空闲端口并记录本次地址。

应用使用一个进程内后台任务执行识别和导出，最大并发为 2。任务状态写入 SQLite；浏览器关闭或刷新不会丢失任务。服务重新启动后，未完成任务回到等待或可重试状态。

## 4. 启动与关闭

### 4.1 首次安装

`首次安装.command` 只需运行一次：

1. 检查 Node.js 与 pnpm 是否满足项目要求。
2. 安装锁定版本的依赖。
3. 执行生产构建和基础自检。
4. 创建默认工作目录及 SQLite 数据库。
5. 赋予启动、关闭脚本可执行权限。

安装过程不得收集遥测，不得安装系统常驻服务。

### 4.2 日常启动

`启动发票工作台.command`：

- 已运行：读取 PID 和端口记录，只打开浏览器。
- 未运行：清理失效 PID，启动本地服务，健康检查通过后打开浏览器。
- 首次选择或重新定位工作目录时，由启动器调用 macOS 原生文件夹选择器；网页不依赖浏览器暴露本地绝对路径。
- 启动失败：在终端显示中文原因及下一步操作，日志不得包含发票文字或密钥。

### 4.3 关闭

`关闭发票工作台.command` 向本地服务发送正常退出信号，停止接收新任务，等待当前文件写入完成后退出。强制关机或进程崩溃时，SQLite WAL 和任务状态用于恢复。

## 5. 工作目录

首次启动允许选择工作目录，默认路径为：

```text
~/Documents/发票工作台/
├── data/
│   ├── workbench.sqlite
│   └── workbench.sqlite-wal
├── invoices/
│   └── 2026-08/
│       └── <内部ID>.pdf
├── exports/
│   └── 发票导出-2026-08.zip
├── backups/
│   └── metadata-2026-08-31.sqlite
└── logs/
    └── app-2026-08-31.log
```

启动器自身使用以下引导配置；它不随工作目录移动，也不包含任何密钥：

```text
~/Library/Application Support/发票工作台/
├── config.json     # 当前工作目录、最近一次端口
└── runtime.json    # PID、本次启动令牌、实际端口；文件权限为 0600
```

启动令牌每次启动重新生成，只用于本机浏览器访问当前进程；启动器在打开网页时注入令牌，应用不得把它写入网址历史、日志或工作目录。

规则：

- 上传时复制文件到工作台目录，原位置文件永不修改、移动或删除。
- 管理副本使用随机内部 ID 命名，原文件名保存于数据库。
- 文件先写临时名，校验完成后原子重命名，避免半文件。
- 工作目录路径保存在引导配置中，SQLite 的非敏感设置只保存一份镜像；目录被移动或不可访问时，启动必须要求重新选择，不能静默创建空目录。
- 所有路径操作在解析后必须仍位于工作目录内，拒绝路径穿越和符号链接逃逸。

## 6. 本地优先识别

### 6.1 识别顺序

1. **PDF 文字层**：优先使用本地 PDF 文本提取，避免对已有文本的电子发票做图像 OCR。
2. **Apple Vision OCR**：扫描 PDF、JPG、JPEG 和 PNG 转为图像后，调用 macOS Vision，语言优先级为简体中文、繁体中文、英文。
3. **OFD 本地解析**：提取 OFD 文本和页面内容；无法结构化时转为图像交给 Vision。
4. **字段解析器**：从本地文本中提取票种、日期、代码、号码、开票方、购买方、不含税金额、税额和价税合计。
5. **置信度判断**：结合 OCR 置信度、字段格式、金额关系和关键字段完整度，决定是否需要人工确认。

本地识别任务不得进行网络请求。

### 6.2 手动云端兜底

- 只有用户点击单张发票上的“使用云端重新识别”后才允许请求云端。
- 点击后先展示提示：将上传哪个文件、发送给哪个供应商、将覆盖哪些草稿字段。
- 用户再次确认后调用云端；取消操作不产生任何网络请求。
- 云端结果进入校对草稿，不能绕过人工确认直接入库。
- 初始云端适配器使用腾讯云通用票据识别，接口仍保持可替换。
- 云端密钥保存在 macOS 钥匙串，不写入源码、`.env`、SQLite、日志或导出文件。
- 未配置密钥时打开设置引导，本地识别和人工录入继续可用。

### 6.3 人工录入

本地与云端识别都失败时，用户可以基于原始文件人工录入。关键字段完成前记录保持草稿状态。

## 7. 数据模型

SQLite 至少保存以下实体：

- **settings**：OCR 偏好、界面偏好和其他非敏感配置；工作目录镜像仅用于诊断，不作为启动依据。
- **source_files**：内部 ID、原文件名、管理副本路径、格式、大小、SHA-256、创建时间。
- **recognition_jobs**：识别方式、本地/云端、状态、错误代码、开始和结束时间。
- **invoice_drafts**：识别字段、每字段置信度、用户修改值和校对状态。
- **invoices**：确认后的正式字段、报销状态、原始文件关联、创建和更新时间。
- **duplicate_matches**：匹配原因、候选发票、处理结果和强制保留原因。
- **export_jobs**：筛选快照、输出路径、状态、错误和完成时间。
- **status_events**：报销状态变更历史。

金额使用 SQLite 整数分存储，例如 `128000` 表示 `1280.00` 元；任何统计都不使用浮点数累计。

## 8. 上传、查重与校对

### 8.1 上传

- 单批最多 100 个文件，单文件最大 20 MB。
- 同时校验扩展名、MIME、文件头和可读取性。
- 每个文件独立处理；单个失败不得中断整批。
- 上传进度、识别进度和错误原因逐文件显示。

### 8.2 重复检测

1. 管理副本写入前计算 SHA-256，完全相同文件默认阻止入库。
2. 识别后优先比较发票代码和号码。
3. 代码缺失时，结合号码、日期、价税合计、票种和标准化开票方判断疑似重复。
4. 重复提示展示判断依据和已存在记录。
5. 用户明确填写保留原因后可以强制保留，导出同名时追加 `-副本2`、`-副本3`。

### 8.3 校对

关键字段包括日期、发票类型、开票方、价税合计、发票号码或唯一凭证号。缺失或低置信度字段醒目标黄；用户确认后才正式入库，初始状态为“待报销”。

## 9. 页面与统计

保留四个一级页面：

1. **总览**：总金额和数量、三种报销状态金额、月度堆叠柱状图、票种和状态占比图、最近发票。
2. **上传发票**：拖拽/选择文件、本地识别、人工录入、手动云端识别和逐文件状态。
3. **发票管理**：按月份、类型、状态和关键词查询，单张或批量改状态，查看原件与删除。
4. **整理导出**：选择范围、预览目录和文件名、生成 Excel 与 ZIP。

桌面端使用左侧导航，宽度不超过 760px 时使用底部导航。所有图表同时显示文字图例、金额、数量和比例，不能只依靠颜色。

报销状态固定为：

```text
待报销 → 报销中 → 已报销
```

允许纠正性回退；导出不会自动改变状态。

## 10. 导出

导出文件名：

```text
日期-类型-开票方名称-发票号码.ext
```

目录：

```text
发票导出-2026-08.zip
├── 发票明细-2026-08.xlsx
└── 2026-08/
    ├── 增值税普通发票/
    ├── 增值税专用发票/
    ├── 铁路电子客票/
    └── 其他票种/
```

规则：

- 非法文件名字符替换为空格，连续空格合并。
- 名称过长时只截短开票方，保留日期、类型和号码。
- Excel 固定包含类型、日期、代码、号码、开票方、购买方、不含税金额、税额、价税合计、报销状态、原文件名、导出文件名和识别时间。
- Excel 日期使用真实日期单元格，金额使用数值两位小数，首行冻结并启用筛选。
- 默认保存到 `exports/`，也可由用户另选目录。
- 生成前列出字段缺失项，不生成名称不完整的文件。

## 11. 备份、恢复与删除

### 11.1 元数据备份

- 每天首次启动，在 SQLite 一致性检查通过后创建一次元数据备份。
- 只保留最近 7 份自动元数据备份。
- 数据库 schema 升级前必须额外创建一份备份，不计入日常 7 份轮换。

### 11.2 完整备份

“一键完整备份”把 SQLite、全部管理副本和非敏感配置打包到用户选择的位置。云端密钥不进入备份。

恢复操作先验证备份结构和文件哈希，再把当前工作目录改名为带时间戳的安全副本；只有验证成功后才切换到恢复内容。

### 11.3 删除

- 用户确认后先写入待删除恢复记录，再把工作台管理副本移入 macOS 废纸篓，不做不可恢复删除。
- 文件移动成功后，在同一个 SQLite 事务中删除正式记录、识别关联和待删除恢复记录。
- 上传前的原始来源文件永远不受影响。
- 文件移动或数据库事务失败时显示未完成；保留恢复记录和可用文件位置，供下次启动完成或撤销。

## 12. 异常处理

- **本地 OCR 失败**：允许重试、人工录入或手动云端识别。
- **OFD 解析失败**：保留原件，尝试本地图像 OCR；仍失败则提供人工/云端选项。
- **云端不可用**：草稿和原文件保持不变，显示供应商请求 ID 或本地错误编号，允许重试。
- **工作目录丢失**：停止写入，要求重新定位目录。
- **SQLite 锁定**：短暂退避重试；持续失败时进入只读模式并提供备份入口。
- **SQLite 损坏**：停止修改，复制损坏文件，执行完整性检查并引导从最近备份恢复。
- **导出失败**：保留筛选快照，可按原范围重试。
- **磁盘空间不足**：写入前检查可用空间；中止后清理临时文件，不删除已有数据。
- **进程异常退出**：下次启动清理孤立临时文件，并恢复等待中的任务。

## 13. 隐私与安全

- 服务只绑定 `127.0.0.1`。
- 所有本地 API 检查请求来源和随机启动令牌，阻止其他网页直接调用高风险操作。
- 发票路径必须位于授权工作目录内。
- 云端 OCR 只通过用户明确二次确认触发，并使用 HTTPS。
- 云端凭证保存在 macOS 钥匙串。
- 日志只包含时间、内部文件 ID、任务阶段和错误编号，不包含 OCR 原文、发票图片、绝对来源路径、访问令牌或云端密钥。
- 日志自动删除 7 天前的文件。
- 应用不包含分析、遥测或自动更新网络请求。

## 14. 验收标准

1. 首次安装后，用户可以双击启动脚本打开工作台；重复双击不会启动第二个服务实例。
2. 本地服务只监听回环地址，其他局域网设备无法访问。
3. 用户可以一次选择最多 100 个受支持文件，单文件最大 20 MB；失败项不影响其他文件。
4. PDF 文字层、图片/扫描 PDF Apple Vision OCR 和 OFD 本地解析按既定顺序执行。
5. 未点击并再次确认“使用云端重新识别”时，不发生发票上传网络请求。
6. 在约定的真实样本集上，核心字段本地识别准确率被量化记录；低于目标的字段必须进入人工校对，不得伪装为高置信度。
7. 完全重复文件和相同代码/号码发票默认被阻止，强制保留必须记录原因。
8. 发票可以单张或批量修改三种报销状态，统计同步更新。
9. 月度金额、类型占比和状态占比与筛选后的明细一致。
10. Excel 行数、金额和字段与选择范围一致，ZIP 目录和文件名符合本设计。
11. 删除管理副本后可以从 macOS 废纸篓恢复，原始来源文件保持不变。
12. 自动元数据备份最多保留 7 份，完整备份可以在验证后恢复。
13. 浏览器关闭、服务重启和单个识别失败不会造成已确认数据丢失。
14. 最近版本的 Chrome、Edge 和 Safari 以及典型手机宽度下可完成核心闭环。

## 15. 实施边界

首版只支持单台 Mac、单个个人用户。系统不提供远程访问、云同步或多人协作。若未来确实需要跨设备或公司使用，再单独设计同步、认证和远程存储，不在当前本地版中预留复杂基础设施。

正式开发前，需要按本设计重写实施计划。此前基于云端多用户架构的计划和未完成分支不再作为实现依据，但保留在 Git 历史中以便追溯。
