# 个人发票整理工作台产品设计

- 日期：2026-08-31
- 状态：设计已确认
- 产品形态：响应式网页
- 目标用户：个人用户

## 1. 产品目标

建设一个面向个人用户的响应式发票整理工作台。用户可以批量上传常见格式和类型的发票，使用云端 OCR/AI 自动提取结构化字段，校对后统一管理报销状态，并通过图表查看金额构成。导出时，系统按月份和发票类型自动建目录，生成 Excel 明细，并将规范重命名后的原始发票一起打包为 ZIP。

首版的成功标准是：减少手工录入和改名工作，可靠阻止重复发票入库，让用户能够在电脑或手机上完成“上传—校对—管理—统计—导出”的完整闭环。

## 2. 首版范围

### 2.1 包含

- 个人账号登录及数据隔离。
- PDF、OFD、JPG、JPEG、PNG 文件上传。
- 单次最多上传 100 个文件，单文件最大 20 MB。
- 常见票种识别，包括增值税普通发票、增值税专用发票、数电票、铁路电子客票、出租车票、机票行程单等。
- 云端 OCR/AI 识别、置信度展示和人工校对。
- 文件级与业务级重复检测。
- 发票查询、筛选和报销状态管理。
- 月份、类型、金额和报销状态统计。
- Excel 明细、规范化目录及 ZIP 导出。
- 电脑、平板和手机端响应式布局。

### 2.2 不包含

- 公司组织架构、部门、报销人和审批人字段。
- 多人协作、角色权限和公司审批流程。
- 财务系统、企业 ERP 或第三方报销平台对接。
- 自动验真、自动报税或自动提交报销。
- 原生 App 或微信小程序。

## 3. 信息架构

工作台包含四个一级页面：

1. **总览**：展示关键金额、数量、月度趋势、发票类型占比、报销状态占比和最近发票。
2. **上传发票**：支持拖拽或选择多个文件，并显示上传、查重、识别和校对进度。
3. **发票管理**：查询、筛选、查看、编辑字段，以及单张或批量更新报销状态。
4. **整理导出**：选择月份、票种和报销状态，预览目录及命名结果，生成 Excel 和 ZIP。

桌面端使用左侧导航，移动端使用底部导航。首版保持相同功能，不在移动端删除关键操作。

## 4. 核心用户流程

### 4.1 上传与识别

1. 用户拖拽或选择一个或多个文件。
2. 前端校验文件扩展名、大小和可读取性。
3. 后端保存原始文件，并计算文件内容指纹。
4. 系统先执行文件级重复检查，再创建云端识别任务。
5. 识别完成后，系统标准化日期、金额、票种和主体名称，并执行业务级重复检查。
6. 非重复发票进入校对页；低置信度字段醒目标黄。
7. 用户确认或修改字段后正式入库，初始报销状态为“待报销”。

批量处理中，每个文件独立显示状态。单个文件失败不得中断整批任务。

### 4.2 报销状态

报销状态严格采用以下三态：

```text
待报销 → 报销中 → 已报销
```

- 新入库发票默认处于“待报销”。
- 用户可以单张或批量修改状态。
- 允许从“已报销”回退，以便纠正误操作。
- 状态修改后，列表、顶部指标和图表同步更新。
- 首版不把导出操作与状态自动变更绑定，避免导出即被误认为已报销。

### 4.3 重复检测

系统采用两层检测：

1. **完全重复**：比较文件内容指纹，发现相同文件时立即阻止后续识别和入库。
2. **业务重复**：优先比较发票代码与发票号码；当字段缺失时，结合开票日期、价税合计、开票方标准化名称及文件指纹判断疑似重复。

重复项默认阻止入库。提示中必须展示匹配依据及已存在发票，用户可以打开原记录核对。用户明确选择“仍然保留”后才允许入库，并记录强制保留原因及关联的原发票 ID。

## 5. 发票数据

每张正式入库的发票至少包含：

| 字段 | 说明 |
| --- | --- |
| 发票类型 | 标准化后的票种 |
| 开票日期 | `YYYY-MM-DD` |
| 发票代码 | 票面存在时保存 |
| 发票号码 | 核心识别字段 |
| 开票方名称 | 用于查询、统计与文件命名 |
| 购买方名称 | 票面存在时保存 |
| 不含税金额 | 票面存在时保存 |
| 税额 | 票面存在时保存 |
| 价税合计 | 统一作为统计总金额 |
| 报销状态 | 待报销、报销中、已报销 |
| 原始文件信息 | 原文件名、格式、大小、存储位置和文件指纹 |
| 识别信息 | 服务商任务 ID、识别时间、原始结果摘要和字段置信度 |
| 重复信息 | 判定结果、匹配依据、关联发票和强制保留记录 |
| 系统信息 | 用户 ID、创建时间和更新时间 |

日期、发票类型、开票方名称、价税合计和发票号码属于关键字段。若特定票种不存在发票号码，则使用该票种可获得的唯一凭证号替代。关键字段缺失或未确认时，记录不能正式入库。

金额统一使用定点小数存储，禁止使用浮点数直接进行汇总。原始识别结果保留必要摘要供排错，但日志和监控中不得记录完整票面内容。

## 6. 统计口径

总览默认展示当前自然月，支持切换指定月份或全年。

### 6.1 顶部指标

- 发票总金额和总数量。
- 待报销金额及数量。
- 报销中金额及数量。
- 已报销金额及数量。

所有金额均按价税合计汇总，只统计当前正式入库的发票。

### 6.2 图表

- **月度柱状图**：每月总金额，并按三种报销状态堆叠显示。
- **发票类型饼图**：默认按价税合计展示占比，可切换为按发票数量。
- **报销状态饼图**：按价税合计展示三种状态的比例。

点击图表中的月份、票种或状态后，联动筛选发票列表。图表必须同时提供文字图例和数值，不能只依赖颜色表达信息。

## 7. 导出设计

### 7.1 选择范围

用户可以按月份、发票类型和报销状态选择导出范围。生成前展示预计文件数量、总金额、缺失字段和预计压缩包大小。

### 7.2 文件命名

导出文件使用以下规则：

```text
日期-类型-开票方名称-发票号码.ext
```

示例：

```text
2026-08-28-增值税普通发票-北京某某科技有限公司-25112000000018475031.pdf
```

处理规则：

- 使用标准化日期、票种和开票方名称。
- 文件扩展名沿用原始文件格式并统一为小写。
- 文件名中的斜杠、反斜杠、冒号、星号、问号、引号、尖括号和竖线替换为空格，连续空格压缩为一个。
- 文件名超过目标文件系统安全长度时，优先缩短开票方名称，日期、类型和发票号码必须保留。
- 用户强制保留的重复发票若发生同名，依次追加 `-副本2`、`-副本3`。

### 7.3 ZIP 目录

```text
发票导出-2026-08.zip
├── 发票明细-2026-08.xlsx
└── 2026-08
    ├── 增值税普通发票
    ├── 增值税专用发票
    ├── 铁路电子客票
    └── 其他票种
```

跨月导出时，每个月使用独立的 `YYYY-MM` 目录。票种目录使用标准化类型名称。

### 7.4 Excel 明细

Excel 每张发票一行，列顺序如下：

1. 发票类型
2. 开票日期
3. 发票代码
4. 发票号码
5. 开票方名称
6. 购买方名称
7. 不含税金额
8. 税额
9. 价税合计
10. 报销状态
11. 原文件名
12. 导出文件名
13. 识别时间

金额列使用数值和两位小数格式，日期列使用真实日期单元格。首行冻结并启用筛选，不使用合并单元格。

## 8. 系统架构

系统采用模块化轻量云应用：

```text
响应式网页
    ↓
后端 API
    ├── 账号与权限
    ├── 发票数据及重复检测
    ├── 对象文件存储
    ├── OCR/AI 识别适配层 → 云端识别服务
    ├── 异步任务队列
    └── Excel/ZIP 导出服务
```

### 8.1 模块职责

- **网页端**：上传、进度展示、字段校对、筛选统计、状态管理和导出操作。
- **后端 API**：认证授权、数据校验、业务规则、重复检测、文件命名及访问控制。
- **数据库**：用户、发票、识别任务、导出任务、状态变更和重复关联。
- **对象存储**：分别保存原始发票和临时导出包，下载使用限时授权地址。
- **任务队列**：处理批量识别、自动重试和 ZIP 生成，避免长请求超时。
- **识别适配层**：把不同云端识别服务的响应转换为统一字段，不让核心业务依赖单一服务商。

首版只运行一套网页应用和后端服务。部署方式需要支持后续水平扩展，但不提前引入多租户组织架构、微服务拆分或复杂消息系统。

## 9. 异常与恢复

- **不支持、损坏或加密文件**：拒绝识别并显示具体原因。
- **上传中断**：保留已完成文件，支持单文件重试。
- **识别失败**：按退避策略自动重试；达到上限后允许人工录入或再次发起识别。
- **低置信度**：字段标黄；关键字段未确认前禁止正式入库。
- **重复发票**：阻止入库，展示匹配依据、原发票和强制保留入口。
- **云服务不可用**：文件安全保留，任务进入等待队列，服务恢复后继续处理。
- **导出前字段缺失**：列出问题发票并引导修改，不生成名称不完整的文件。
- **导出失败**：保留选择条件和任务记录，用户可以原范围重试。
- **部分任务失败**：批量任务返回逐文件结果，不以一个失败项覆盖已成功结果。

用户可以在任务记录中查看成功、失败、等待和重试状态。错误提示必须面向用户描述可采取的下一步，同时保留不含敏感票面数据的内部错误编号。

## 10. 安全与隐私

- 全站使用 HTTPS。
- 所有发票、任务和下载请求必须校验当前用户所有权。
- 原始发票与导出包不提供永久公开地址。
- 密钥、云服务凭证和存储凭证只存在于服务端环境变量或密钥管理服务中。
- 日志不得记录完整发票图片、完整 OCR 原文、访问令牌或下载签名。
- 用户确认删除发票后，系统删除业务记录、原始文件及关联识别数据；任一环节失败时展示未完成状态并继续重试，不能把部分删除显示为成功。
- 临时 ZIP 保留 24 小时后自动删除，过期后允许用户按原条件重新生成。
- 对上传、识别和导出接口设置用户级频率和并发限制，防止误操作产生异常费用。

## 11. 非功能要求

- 最近版本的 Chrome、Edge 和 Safari 可正常使用。
- 电脑、平板和手机宽度下均可完成上传、校对、查询、状态修改和导出。
- 普通页面操作在正常网络环境下应于 2 秒内反馈。
- 上传、识别和导出采用可见进度及异步任务，不把耗时任务包装为同步页面请求。
- 批量列表使用分页或虚拟化，避免发票数量增长后阻塞页面。
- 金额统计和导出结果使用同一套后端查询口径，避免页面与 Excel 不一致。

## 12. 验收标准

1. 用户可以一次选择最多 100 个受支持文件；不合规文件被逐一指出，不影响其他文件。
2. 系统可以为受支持票种返回统一字段，并允许用户在入库前逐项校对。
3. 在双方约定的真实样本集上，日期、类型、发票号码或唯一凭证号、开票方名称、价税合计等核心字段准确率目标不低于 95%。
4. 相同文件内容可以被文件指纹拦截；相同发票代码和号码可以被业务规则拦截。
5. 疑似重复提示包含判断依据和原发票入口；只有用户明确确认后才可强制保留。
6. 发票支持单张和批量修改为待报销、报销中、已报销，相关统计同步更新。
7. 月度金额、发票类型占比和报销状态占比与筛选后的发票明细一致。
8. 导出的 Excel 行数、金额和字段与所选发票一致，ZIP 目录和文件名符合本设计。
9. 非法文件名字符、过长名称和强制保留的同名副本均按既定规则处理。
10. 识别或导出失败后可以重试，已经成功的同批文件不会被重复创建。
11. 未登录用户或其他账号不能访问当前用户的发票、识别结果和下载地址。
12. 最新版 Chrome、Edge、Safari 以及典型手机宽度下可以完成核心闭环。

## 13. 实施边界

产品设计不固定具体 OCR 供应商、云厂商或前后端框架。实施阶段应以本设计规定的格式覆盖、字段准确率、异步处理能力、数据安全和费用可控性为准选择技术，并通过识别适配层保持可替换性。

正式开发前，需要基于本设计另行编写实施计划，拆分数据模型、接口、页面、异步任务、识别适配、导出和测试工作。实施计划获得确认后才能开始编码。
